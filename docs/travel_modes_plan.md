# 이동수단별 시간(대중교통·자차·도보)을 배정에 넣는 방법

- 작성: 2026-11-16 (각 사이트 화면을 직접 확인함. '확인 필요'는 아직 보지 못한 것)
- 출발점: 퇴원 어르신 병원동행은 **대중교통이 기본**이다. 자가용이 있으면 가족이 동행하는 경우가 많고,
  기관 차량은 수가 아주 적다. 그런데 지금 엔진은 모든 이동을 **자동차(OSRM driving)** 로 계산한다.
  - 동행 점유시간: `planner/data.py:155`, `verifier/`(155행), `simulator/experiment.py:40` 이 세 곳이 집→병원→집을 자동차 시간으로 계산한다.
  - ODsay 대중교통(`adapters/transit.py`)은 표본 5건만 조회한 참고용이고, 배정에는 쓰지 않는다.
  - 결과적으로 동행 1건의 점유시간이 짧게 잡혀 있다. 그래서 "하루에 몇 명을 도울 수 있나"가 실제보다 크게 나올 수 있다.

## 1. 민간 지도 API로는 왜 안 되나 (확인 결과)

| 공급자 | 한국에서 되는 것 | 우리에게 맞나 |
|---|---|---|
| Google Maps Platform | 공식 사용 범위 표에서 대한민국은 지도·지오코딩만 ⬤. **운전 경로·도보 경로·자전거 경로는 모두 '—'(제공 안 함)** | 자차·도보는 아예 안 된다. 대중교통도 이 표에는 나오지 않음(확인 필요). 판매용으로는 요금·저장 제한 문제가 남음 |
| 네이버 클라우드 Maps | API 목록: Static/Dynamic Map, Geocoding, Reverse Geocoding, **Directions 5·15(경로 탐색)**. 대중교통 길찾기 API는 목록에 없음 | 자차만 된다. 대중교통은 안 됨 |
| 카카오 | 공개 API는 자동차 길찾기 중심(대중교통 API 없음으로 알고 있음, 확인 필요) | 자차만 된다 |

네이버 지도나 구글 지도 앱 화면에서 보이는 대중교통·도보 시간은 앱 기능이다. 개발자 API로는 제공되지 않는다.
그래서 "장소 검색하면 수단별 시간이 나오는" 기능은 **수단마다 다른 출처를 붙여서** 만들어야 한다.

## 2. 수단별 출처 (권장 조합)

| 수단 | 출처 | 비용·조건 | 상태 |
|---|---|---|---|
| **자차** | OSRM `driving`(자체 서버, OpenStreetMap) + 국가교통정보센터 소통정보로 시간대 보정 | 호출당 비용 없음, 전국 가능 | 운영 중. 보정은 `public_data_plan.md` |
| **도보** | OSRM `foot` 프로필(같은 OSM 지도로 도보용 서버 하나 더) | 호출당 비용 없음, 전국 가능 | 추가 필요(준비 스크립트에 프로필만 추가) |
| **대중교통** | ① 지금: **ODsay 대중교통 길찾기**(디지털융합플랫폼 A03, 승인됨) ② 장기: 공공 버스·지하철 자료로 **자체 대중교통 경로 서버** | ① 플랫폼 경유라 지금은 무료. 판매 단계에서는 ODsay와 따로 계약해야 함(조건 확인 필요) ② 호출당 비용 없음 | ① 표본 조회 성공(4/5건 ok, 1건은 '700m 이내' 오류 → 도보로 처리할 대상) |

장기 ②에 대한 확인 결과는 다음과 같다.
- 공공데이터포털에서 'GTFS'(대중교통 경로 계산의 표준 형식)를 검색하면 **0건**이다. 전국 표준 파일이 없다.
- 재료는 있다:
  - 국토교통부 (TAGO) 버스노선정보 API: 노선, 노선별 경유정류소. 활용신청 5,128건
  - 한국교통안전공단 버스노선정보(파일)
  - 지자체별 노선·운행시간 파일
- 이 재료로 '배차간격 기반' 경로 자료를 직접 만들어 OpenTripPlanner(공개 소프트웨어)에 넣으면, OSRM처럼 자체 서버로 돌릴 수 있다.
- 다만 작업량이 크다. M3 이후 판매 준비 단계의 과제로 둔다.

## 3. 효율적으로 붙이는 방법 — "전부 조회하지 않는다"

지금 행렬은 650,442칸이다. 이 칸을 모두 ODsay로 조회하는 것은 불가능하고 필요하지도 않다. 수단별로 필요한 양이 다르다.

### 3-1. 동행 구간(어르신 집 ↔ 병원): 실제 조회 + 영구 저장
- 어르신과 병원은 고정이다. 그래서 (집, 병원) 쌍은 날마다 반복되므로 **한 번 조회해 저장하고 다시 쓴다**.
  - 필요한 양 = 실제로 동행 요청이 있었던 쌍 × 2방향
  - 가상 권역 기준 수백 건 수준이다(정확한 수는 생성 후 계산).
- 동행 1건의 점유시간 = 대중교통(집→병원) + 병원 체류 + 대중교통(병원→집).
  - 대중교통이 700m 이내라 경로가 없으면(ODsay −98), OSRM 도보 시간을 쓴다.
  - 조회에 실패하면 **0분으로 바꾸지 않고**, '자동차 시간으로 대체'라고 표시한다(이미 `display_minutes` 규칙이 있음).
- 요청마다 `escort_mode`(대중교통 / 자차·택시 / 복지콜)를 둔다. 기본값은 **대중교통**이다.
  - 휠체어 등으로 다른 수단이 필요한지는 **담당자가 정한다**. AI가 보행 능력을 판정하지 않는다.

### 3-2. 인력의 다음 집까지 이동: 인력별 수단 + 대중교통은 '보정 모형 → 확정안만 실제 조회'
- 인력마다 `travel_mode`(자차 / 대중교통)를 둔다.
  - 자차 인력은 지금처럼 OSRM 행렬을 쓴다.
- 대중교통 인력의 행렬은 다음 순서로 만든다.
  1. **모형**: 도보 OSRM과 '자동차 시간 × 계수 + 대기·환승 상수' 중 짧은 쪽을 쓴다.
     계수는 ODsay 표본 300~500쌍으로 맞추고, 출처는 `estimate`, 맞춘 오차는 summary에 남긴다.
  2. 엔진은 이 모형 행렬로 계산한다(30초 제한 유지).
  3. **확정 후보안의 실제 연결 구간만** ODsay로 조회한다. 하루 수십 건 수준이다.
     조회한 시간으로 검증기를 다시 돌려, 늦게 도착하는 구간이 생기면 배정안에 표시하고 다시 계산한다.
- 이렇게 하면 호출량은 '하루 확정 구간 수'에 비례한다. 행렬 크기와 상관없다.

### 3-3. 시간 기준 표시
- ODsay에는 출발 시각 요청변수가 없다(시간 기준 미지정). 그래서 출근 시간대 배차와 낮 시간대 배차의 차이는 반영되지 않는다.
- 화면에 "대중교통 · 시간 기준 미지정"을 그대로 표시한다(이미 구현).
- 시각별 계산은 장기 ②(자체 서버)에서 해결한다.

## 4. 효과 증명에 주는 영향 (중요)
- 동행 점유시간이 길어지면 같은 인력으로 맡을 수 있는 요청이 줄어든다. 그러면 부하율 ρ가 올라간다.
- 지금까지의 실험 결과(자동차 기준)는 **'자동차 가정'이라고 보고서에 밝혀야 한다.**
- 실험을 `자동차 가정 / 대중교통 기본` 두 시나리오로 다시 돌려 비교한다.
  - AI 배정의 이점(묶기·순서 조정)이 대중교통에서 커지는지 작아지는지 보는 것 자체가 결과다.
  - 숫자는 계산에서만 나온다.

- **3 완료**: `config/region.yaml escort_travel.default_mode: transit`. `planner.data.load_travel` 이 집↔병원 구간만 바꿔
  엔진·기준선·검증기·시뮬레이터가 같은 값을 쓴다. 화면 '하루 배정 비교' 왼쪽에 동행 구간 출처 건수 표시.
- 표본 3일(11/02~04, 전체 요청) 계산: 동행 왕복 이동 평균 14~15분(자동차) → 49~58분(대중교통).
  배정 건수는 날짜·방식에 따라 같거나 줄었다(예: 11/02 최적화 40건 → 32건). 세 방식 모두 위반 0.
  → 4단계(30일·다중 시드 두 시나리오 재실험)에서 확정한다. 이 3일 숫자를 결론으로 쓰지 않는다.
- **4 진행 (2026-11-17)**: ρ 0.9 세 시나리오(자동차 / 대중교통 / 수요 고정) 30일 × 시드 10개 완료, 위반 0.
  결과는 `docs/submission/numbers_m2.md` 4절, 보고서 초안 3.1절. ρ 0.6·1.1도 완료(위반 0).
- **5 진행 (2026-11-17)**
  - 인력별 `travel_mode`(car / transit)와 `worker_travel` 표를 엔진·기준선·검증기·시뮬레이터에 넣었다(커밋 cf7bb09).
    인력 이동만 수단 표로 계산하고, 동행 집↔병원은 공용 표. 표에 없는 구간은 자동차 시간으로 메우지 않는다.
  - 보정 모형(커밋 99b4683): ODsay 표본 400쌍 → `min(1.48 × 자동차분 + 20.3, 도보) + 여유 9.4분`.
    여유가 없으면 엔진이 모형이 짧게 잡은 구간을 골라 실제로는 늦는 배정안이 나왔다(재조회로 확인).
  - 확정 후보안 재조회 `python -m adapters.fetch worker-plan`: 연결 구간만 실제 조회 → 다시 검증 → 늦는 인력 일정만
    같은 순서로 시각 재조정. 표본 4일 모두 2회 안에 확정, 빠진 요청 0.
  - 인력 대중교통 비율 0% / 50% / 100% 시나리오 실험: `numbers_m2.md` 5절.

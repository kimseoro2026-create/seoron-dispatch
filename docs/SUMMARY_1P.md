## 2. 결과

**실험 조건:** [일수]일 × [시드 수]시드 × 부하율 ρ = 0.6 / 0.9 / 1.1 × 3방식
**출처:** `data/experiments/summary-full-<시각>.csv`

### 부하율별 적기 배정률 (30일 × 3시드, 각 90관측)

| ρ | 신청순 | 근거리 | 최적화 | 위반 |
|---|---|---|---|---|
| 0.6 (여유) | 60.1% ± 6.6%p | **63.3% ± 7.0%p** | 62.2% ± 6.8%p | 0건 |
| 0.9 (포화 직전) | 53.5% ± 5.0%p | **61.6% ± 5.0%p** | 61.0% ± 5.8%p | 0건 |
| 1.1 (초과) | 51.4% ± 5.2%p | **61.3% ± 4.7%p** | 61.1% ± 5.4%p | 0건 |

출처: `data/experiments/summary-full-20261108-233333.csv`

**핵심 결론:** 신청순 → 동선 고려 방식으로 바꾸면 **+7~8%p**. 이건 모든 조건에서 일관된다.

**확실하지 않은 것:** 최적화가 근거리를 이기지 못한다(0.2~1.0%p 뒤짐, 표준편차보다 작음).
고유인원은 ρ=1.1에서 근소하게 앞선다(34.80 vs 34.76) — 오차 범위 안이다.
따라서 "OR-Tools 최적화가 단순 근거리보다 낫다"는 주장은 **이 실험으로 할 수 없다.**

## 3. 한계

1. **하루 표본으로는 주장할 수 없다.** 30일 전체 실험 결과만 근거로 쓴다.
2. **동행 요청 시간창이 20분으로 좁다.** 생성기가 `예약 − 이동 − 30 ~ 예약 − 이동 − 10` 으로
   고정해 만들어 폭이 항상 20분이다. 실제 기관이 이렇게 운영하는지 확인되지 않았다.
   좁은 창은 탐욕적 기준선에 불리하게 작용할 수 있어 비교가 기울 가능성이 있다.
3. **인구 데이터가 아직 모의값이다.** 병원은 실제 좌표를 쓰지만, 행정동 고령인구는
   가상동 6개짜리 모의 데이터다. 플랫폼 인구 API 상세 화면을 받으면 교체한다.
4. **비용을 계산하지 않았다.** 인건비·교통비 단가가 확정되지 않아 "동일 예산" 비교를 내지 않는다.
   시간과 배정량만 보고한다(PRD 13장).
5. **미래 정보를 쓰지 않는다.** 취소·지연은 계획 시점에 알 수 없으므로 배정에서 제외하지 않는다.
   시뮬레이터에서 이벤트로 재생하는 것은 M2 작업이다.
6. **AI는 판정하지 않는다.** 자격·의료적 필요·자립보행 여부를 확정하지 않고, 배정 확정은 담당자가 한다.

## 1. 만든 것

퇴원 어르신의 **병원동행·가사지원 요청**과 돌봄 인력의 **근무시간·휴게·자격·동선**을 함께 계산해,
담당자에게 배정안을 제안하는 시스템. 확정은 항상 담당자가 한다.

- **가상 권역**: 실제 병원 위치(심평원 병원기본목록 API, 400곳) + 합성 어르신 300명·인력 20명, 평일 30일 요청 1,810건.
  이동시간은 자체 OSRM 도로 경로로 계산(519,120구간).
- **배정 3방식**: 신청순(기존 방식) · 근거리(기존 방식) · 최적화(OR-Tools Routing). 병원동행은 집→병원→집을 한 덩어리로 다룬다.
- **독립 검증기**: 엔진 코드를 쓰지 않고 하드 제약(요청당 1명·일정 겹침·휴게·자격·시간창·예약 도착·근무시간·초과근무·경로 없음)을 다시 검사.
  검증을 통과하지 못한 결과는 배정안으로 보여주지 않는다.
- **시뮬레이터**: 30일 × 3시드 × 부하율 3단계(ρ 0.6/0.9/1.1) 실험. 취소·지연은 **통보 시각에만** 반영(미래 정보 금지).
- **화면(Streamlit)**: 날짜·방식 선택 → 인력별 타임라인 → 방식 비교표 → 미배정 사유 → 담당자 승인 → 30일 실험 결과.
- 자동 테스트 128개.

## 2. 결과 (하루 평균, 각 90관측, 하드 제약 위반 0건)

| ρ=0.9 (인력이 바쁜 날) | 신청순 | 근거리 | 최적화 |
|---|---|---|---|
| 적기 배정 (건/일) | 29.3 | 33.8 | **34.5** |
| 적기 지원 고유 인원 (명/일) | 28.0 | 32.0 | **32.7** |
| 총 이동 (분/일) | 220 | 174 | **153** |

- **같은 인력·같은 요청으로, 신청순 대비 하루 4.7명(+16.6%) 더 제때 돌봄을 받았다(최적화).** 이동은 30.4% 줄었다.
  근거리 규칙만으로도 +4.0명(+14.3%)이며, 최적화는 근거리보다 하루 0.7명 더 돌보면서 이동을 21분 줄였다.
- 최적화 vs 근거리, 270개 날짜·시드 조합: 배정 건수가 많은 날 75, 적은 날 0, 같은 날 195.
- 부하가 높을수록 차이가 커진다: 신청순 대비 고유 인원 ρ 0.6 +5.2% → ρ 0.9 +16.6% → ρ 1.1 +21.6%(1.22배 적기 배정).
- 취소·지연 재생(ρ=0.9, 90일): 취소로 빈 자리를 다른 요청으로 다시 채운 건수 신청순 208건 · 근거리 58건.
  지연 통보 514건 중 202건은 그날 안에 지켰다(다른 인력에게 넘겨 지킨 건 3~6건).

## 3. 한계 (정직하게)

- **최적화의 개선폭은 근거리 대비 작다**(하루 +0.7명, 72%의 날은 배정 건수가 같다). 최적화는 근거리 배정을 첫 해로 받아
  OR-Tools 가 10초 동안 개선하는 방식이며, 최적임이 증명된 해가 아니다. 근거리 해 없이 시작하면 10초 안에 좋은 해를 찾지 못했다.
- 제출서의 **'1.45배 지원'·'31% 절감'은 아직 확인되지 않았다.** 이번 실험에서 가장 좋은 조건은 적기 배정 1.22배(ρ 1.1, 최적화),
  이동 30.4% 감소(ρ 0.9)였다. 비용 모델이 없어 비용 절감률은 측정하지 않았다.
  비용 모델이 없어 절감률은 측정하지 않았다(이동시간 감소율은 위 표 참고).
- 미배정의 대부분이 '시간창 충돌'이다. 합성 데이터에서 동행 픽업 시간창을 20분으로 좁게 만든 가정 때문이며,
  실제 기관의 시간창 폭은 확인이 필요하다. 그래서 어떤 방식도 평균 적기율이 64%를 넘지 못한다.
- 고령인구는 아직 모의값이다(인구 API 요청변수 미확인). 병원 위치만 실제 공공데이터다.
